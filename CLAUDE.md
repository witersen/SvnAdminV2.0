# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

SVNAdmin2 is a web GUI for administering a Subversion server. It manages repositories, SVN users/groups/aliases, per-path authz permissions, hooks, backups, scheduled tasks, LDAP, mail/push settings, and updates by reading and writing SVN's `authz`, `passwd`, `httpPasswd`, and `svnserve.conf` files and invoking `svn`, `svnadmin`, `svnserve`, `httpd`, and `htpasswd`.

- Backend: plain PHP 8.3.36+ (8.3.x recommended), no framework and no Composer; third-party code is vendored in `02.php/extension/`. This floor is enforced by `02.php/config/version.php` and is required for the PHP2Shell fixes (CVE-2026-109618 / CVE-2026-109619).
- Frontend: Vue 2 + Vue Router 3 + View UI (iView) 4, bundled with webpack 2.
- Storage: SQLite by default (MySQL supported), plus files under `/home/svnadmin`.
- Linux only at runtime (needs `pcntl`, Unix sockets, SVN, Apache). On Windows use the Docker image.

## Repository layout

Top-level numbering mirrors the deployment package layout:

- `01.web/` — frontend source. Build output (`dist/`) is copied into the same document root as the PHP app.
- `02.php/` — PHP app; its contents map to `/var/www/html/` in production.
- `03.cicd/` — Jenkinsfile, Docker image definition (`svnadmin_docker/`), and source-package build scripts.
- `04.update/` — historical per-version upgrade payloads (`update/code`, `update/index.php`, `update/templete`). These are release artifacts: change `01.web/` or `02.php/`, not these copies.
- `00.static/` — images used by the README.

## Commands

### Frontend (`01.web/`)

```bash
npm install
npm run init     # first run: writes src/config/env.js and generates index.html
npm run dev      # webpack-dev-server on 127.0.0.1:8081 with hot reload
npm run build    # writes dist/ (env.js = "production")
```

`src/config/env.js` is generated by both webpack configs and is gitignored. The dev server proxies `/api.php` to a hardcoded remote host (`sas2.witersen.com:9091`) in `webpack.dev.config.js`; point it at your own backend for local development.

There is no lint script, no test runner, and no automated test suite in this repository.

### Backend / CLI (`02.php/`, or `/var/www/html/server/` in production)

```bash
php server/install.php           # install/reconfigure SVN, Apache, SASL; run as root
php server/svnadmind.php start   # start daemon in the background
php server/svnadmind.php stop
php server/svnadmind.php console # foreground debug mode; stop the daemon first
php server/own.php               # print the web user's uid/gid (for chown)
```

The daemon refuses to start on non-Linux systems or when `pcntl_*` / `shell_exec` / `passthru` are disabled. Every API request probes its socket, so the backend is effectively unusable without it.

### Docker / CI

- Image build: `03.cicd/svnadmin_docker/dockerfile` (Rocky Linux 9 + REMI PHP 8.3 + php-fpm + Apache/SVN; frontend built in a separate `node:14.21.3-bullseye` stage and copied into `/var/www/html`). `start.sh` starts php-fpm, svnserve, saslauthd, crond, atd, and `svnadmind`, then runs Apache in the foreground.
- CI: `03.cicd/Jenkinsfile` builds on commit messages containing `[ci]` (also `Merge*`); `[test]` triggers Sonar. `03.cicd/local_build.sh` builds the image and a source archive.
- Read-only smoke test for a running container: `bash 03.cicd/smoke_test.sh <container> http://127.0.0.1:<port> admin admin` (login/captcha, list and settings endpoints, PHP error log check).
- The release version is hardcoded in several places: `02.php/config/version.php`, the `TAG` in `03.cicd/Jenkinsfile`, `01.web/src/views/login/index.vue`, and `01.web/src/views/setting/index.vue`. Bump them together (currently 2.5.11).

## Architecture

### HTTP request lifecycle

All requests enter through `02.php/api.php` with query parameters `c` (controller), `a` (action), `t` (client type) and a JSON body:

```
POST api.php?c=Svnrep&a=GetRepList&t=web
Header: token: <url-encoded token>
```

`api.php` validates PHP version, `open_basedir`, disabled functions, and daemon availability, opens a Medoo PDO connection, then instantiates `app\controller\<c>` and calls `-><a>()`. Controllers are thin: they construct the matching `app\service\<c>` and return `json2($serviceResult)`.

Every response is `{code, status, message, data}` (`app/function/message.php`). `code` 401 means auth/token problems; `status` 1 = success, 0 = failure. `json1()` / `json2()` terminate the request.

### Authentication and roles

`app/controller/base/Base.php` runs before every controller action:

- `config/router.php` defines public whitelists per `t` type (`web`, `mini`) and the routes an SVN user (role 2) may call.
- Tokens are `roleId|userName|startTime|endTime|hmac` (separator from `config/sign.php`, 6-hour expiry), verified with HMAC-MD5. The token is stored on the user row, so logging in elsewhere invalidates the previous token; logout records tokens in `black_token`.
- Roles: `1` administrator, `2` SVN user, `3` sub-administrator.
- Role 3 permissions come from `subadmin.subadmin_functions` (a flat `Controller/Action` list) produced from the permission tree in `app/service/base/Base.php::$subadminTree`.
- On login, `Base::GetDynamicRouting()` filters `$route` (also in `app/service/base/Base.php`) by role and returns the route tree; the frontend stores and registers it dynamically.

Adding an endpoint therefore usually touches:

1. a method in `app/controller/<X>.php` (delegating to the service),
2. the implementation in `app/service/<X>.php`,
3. `app/controller/base/Base.php` `$subadminTree` if sub-admins should be able to receive it,
4. the frontend call `this.$axios.post("api.php?c=X&a=Y&t=web", data)`,
5. `config/router.php` only if it must work without a token or for role 2.

### Service and shell layers

- Services (`app/service/`) hold the business logic: parse and write SVN config files, query the DB with Medoo, and run system commands.
- `config/svn.php` defines all managed paths (default `/home/svnadmin`): `rep/`, `authz`, `passwd`, `httpPasswd`, `svnserve.conf`, `logs/`, `backup/`, `crond/`, `hooks/`, `sasl/`, `templete/initStruct/01`.
- `app/function/ipc.php` provides `funShellExec($cmd, $daemon = false)`. With `$daemon = true` the command is sent over the Unix socket to `svnadmind` (normally running as root); otherwise it runs in the web process. Use the daemon for privileged or long-running operations.
- Global helpers are loaded by the `auto_require()` pattern in `Base.php`; configs are loaded lazily via `Config::get('name')` (a plain `include config/name.php`).
- `config/bin.php` holds absolute paths to `svn`, `svnadmin`, `svnserve`, `httpd`, `htpasswd`, etc. `extension/Witersen/SVNAdmin.php` wraps common SVN operations.

### Daemon and task queue

`02.php/server/svnadmind.php` is CLI-only and Linux-only. The master listens on `server/svnadmind.socket` and forks a child per request; a separate worker loop polls the `tasks` table every 3 seconds and executes `task_cmd` with `passthru` (statuses: 1 queued, 2 running, 3 finished, 4/5 failed/stopped). Long operations (repository dump/load, backups, sync) and privileged file writes go through this daemon.

Starting the daemon rewrites `config/sign.php` with a new signature, which invalidates all existing login tokens.

### Frontend

- `src/main.js` sets up ViewUI, hash-mode Vue Router, and a global Axios instance, and installs request/response interceptors.
- The token lives in `sessionStorage.token` and is sent as the `token` header (URL-encoded). A `code == 401` response clears the session.
- Only `/login` is a static route (`src/router.js`). After login, the route tree returned by the backend is added via `router.addRoute`; component paths are strings like `repositoryInfo/index.vue`, resolved lazily from `src/views/`.
- Views call the API directly, e.g. `.post("api.php?c=Statistics&a=GetDiskInfo&t=web", data)`.
- `src/views/distribute/` is not referenced by any route (legacy).

### Database

SQLite is the default at `/home/svnadmin/svnadmin.db` (`config/database.php`; a MySQL config is commented in the same file, schema in `templete/database/mysql/svnadmin.sql`). Tables: `admin_users`, `svn_users`, `subadmin`, `svn_groups`, `svn_reps`, `svn_user_pri_paths`, `svn_second_pri`, `options` (many values are PHP-serialized blobs), `tasks`, `crond`, `logs`, `black_token`, `verification_code`.

## Conventions and caveats

- Backend code requires PHP 8.3.36+ (`??` is available). Keep `config/database.php` at `PDO::ERRMODE_SILENT` unless you deliberately migrate Medoo's error handling to exceptions; Medoo 1.7 expects `prepare()`/`execute()` to return `false`. The frontend still uses old tooling (webpack 2, Babel 6), so modern JS may need transpilation.
- Comments, UI strings, and commit messages are Chinese; keep that style.
- Do not edit vendored code in `02.php/extension/` (Medoo, PHPMailer, Verifycode, Witersen wrappers) or the generated copies in `04.update/`; change the sources in `01.web/` and `02.php/`.
- Changing the paths in `config/svn.php` requires re-running `server/install.php` when data already exists.
- There is no test suite: verify changes by running the app (Docker or a Linux host with the full stack) and exercising the affected endpoint or UI manually.
